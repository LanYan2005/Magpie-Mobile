# Magpie 移动端 UI 复刻计划

更新于 2026-11-25。第 1 步的实现和交互回归已完成。Android/iOS 真机截图对照待补。后续实现从第 2 步开始。

## 复刻基准

以用户在本轮上传的桌面 Magpie **Agent、供应商、资源库**三张截图，以及与截图最相符的上游 GUI 源码为准。截图位于[原对话](alma://thread/mwvjq7u89k0smfoq62u)。上轮 Agent 页取材于 `yetone/magpie` 的 `eab4b006d52b818cd91bd2d10b3918782cf535db`，见 `THIRD_PARTY_NOTICES.md`。开始实施时固定经核对的 UI 提交，逐页登记原文件、字段顺序、动作和状态。其余页先查原版，缺证据时标待核。设计目标是栏目层级、分组、控制位置、状态、图标和文案尽量 1:1。手机只因安全区、触控、窄屏或系统字体而调整排版。

现有桌面名和品牌使用 Magpie。测试与对照图使用合成记录，不复制参考图里的账号、凭据片段、本机路径或实际运行状态。

## 实施顺序与验收

### 1. 导航与侧栏

- [x] 共享顶栏默认采用截图方案。左上角加侧栏切换按钮。宽屏展开停靠侧栏，选中栏目后侧栏保持展开。窄屏打开覆盖抽屉，选中栏目后自动收起。点击同一按钮、遮罩或系统返回可关闭，关闭后恢复焦点。旋转或跨宽窄屏时保留选中栏目和页面状态，宽屏记住展开偏好，窄屏进入时默认收起。
- [x] 一级入口遵循本计划指定顺序 `Agent → 会话 → 资源库 → 供应商 → 路由 → 网关 → 用量 → 脱敏 → 插件`。英文为 `Agent → Sessions → Library → Providers → Routing → Gateway → Usage → Redaction → Plugins`。窄屏横向滚动顶栏并把选中标签滚入视野，侧栏可直达全部栏目。设置作为工具入口。
- [x] Agent 成为默认首屏。当前概览里的真实启停和监听状态迁到「网关」。资源入口统一为「资源库 / Library」。用中性背景、分隔线、栏目标题和紧凑行统一壳层。保留浅深色、文字缩放和减少动态效果。
- 交互验收覆盖 320、390 和 1024 逻辑像素，验证两处导航均可到达九个栏目、新导航触区至少 44、选中标签自动滚入视野、抽屉关闭恢复焦点、语言切换和旋转保留选择，以及返回资源库后保留 MCP 子栏目与滚动位置。
- 上游基准为 `b711745b69a551b95b8a59a694c205f6ff3556ca`，通过 `gh api` 取得两份文件。上游根据屏宽切换顶栏、分组侧栏或手机底栏，侧栏模式有面包屑和上下文工具。本次按计划保留共享顶栏，在 700 逻辑像素切换停靠侧栏与覆盖抽屉，右侧提供设置。刷新、更新、查找和侧栏二级入口尚未接入。[app.js](https://github.com/yetone/magpie/blob/b711745b69a551b95b8a59a694c205f6ff3556ca/internal/gui/assets/app.js#L23947) · [app.css](https://github.com/yetone/magpie/blob/b711745b69a551b95b8a59a694c205f6ff3556ca/internal/gui/assets/app.css#L241)
- [ ] Android/iOS 真机截图与桌面参考图的视觉对照待补。

### 2. Agent 页

- [ ] 对齐说明、更新栏、紧凑列表、底部「显示其余 / 管理」和「安装其他 Agent」。每行按截图组织图标、名称及版本、接入状态、详情、模型选择和接入开关。手机允许按同样的阅读顺序分两行。
- [ ] 复用已实现的详情和模型编辑。系统接入、版本发现、更新等动作由真实能力决定可用性，状态与计数来自真实数据。缺少对应功能时显示明确的平台说明。
- 验收：与原版一一检查字段和动作，没有拿演示条目、更新数量或点击无反馈的按钮充当已实现行为。

### 3. 供应商页

- [ ] 将主体改成**按供应商分行**。一行呈现品牌图标、名称、域名和模型数、关联 Agent、账号状态、启停及详情。顶部安排搜索、选择和账号打码。列表下方放已关闭分组和添加供应商；导入入口提供授权后的文件选择。
- [ ] 将 Anthropic、Chat、Responses、Gemini、System One 移入供应商详情的协议配置。使用供应商、账号、模型和协议的真实数据关系。现有每协议一个上游从旧配置迁入新结构，迁移失败时保留原始配置并显示错误。上游凭据与本机访问凭据分离，日志和截图不显示密钥。
- 验收用至少两个合成供应商验证搜索、选择模式、账号打码、开关、已关闭分组和详情。模型数从供应商/账号已配置的模型清单计算，关联 Agent 来自实际绑定，账号状态来自已知的配置或检测结果。由「供应商 → 详情 → 协议配置」逐级返回时保留原筛选与位置。保存、重启及迁移后，使用本地测试上游核对网关使用所选账号、协议端点和认证方式，并确认禁用后停止选用该供应商。视觉和真实路由分别记录验收。

### 4. 资源库

- [ ] 将 Skills 和 MCP 放回二级栏目「技能」「MCP 服务器」。核对原版的其它二级栏目和顺序，包括指令、记忆、Hooks、环境变量、子代理、斜杠命令、规则及插件类栏目。按已核实的源码进行映射。
- [ ] 对齐列表工具区、排序/选择、数量、资源行、按 Agent 的关联操作和开关。首轮继续执行既定范围「管理与导出」。实际写文件及系统分享单独验收，`stdio` 只管理配置。目标目录由系统选择器或目标客户端配合处理。
- 验收：从「资源库」能找到 MCP 和技能，增改、筛选、排序和导出可用性与界面一致。未实现发现、备份、按 Agent 部署等能力时明示，保留 Android/iOS 沙箱边界。

### 5. 其它栏目及收尾

- [ ] 逐页补齐会话、路由、网关、用量、脱敏、插件的截图和源码对照，再实现页面及真实数据。多账户选路、协议转换、脱敏等尚缺的底层行为写入差异表，同一项在验收通过前保持待完成状态。
- [ ] 逐页记录上游出处、Android/iOS 截图、交互测试和平台差异。保留原版品牌与授权出处。分别记录 `flutter analyze`、`flutter test`、Android 构建/真机及 iOS 构建/真机结果。未实测平台标待验证。

## 中断与恢复

每做完一阶段就在本文件勾选对应项，并写下提交号或改动文件、测试结果及下一条未完成项。阶段进行到一半时，在下方「检查点」追加一行：当前子项、已改文件、最近一次验证结果、下一步。恢复时先读取本文件、检查 Git 工作区和未提交差异，区分本计划开始前已存在的未提交改动（见文件开头）和本轮新增改动，再从最近检查点或第一条未勾选任务继续。页面通过的标准是截图与交互对照均有记录。
